# 产品迭代路线

## 市场参考

当前同类产品大致分为四类：

- 自动填表型：以 Simplify Copilot 为代表，强调自动填写申请表、生成定制简历/求职信，并追踪求职流程。
- 岗位追踪型：以 Teal、Huntr 为代表，强调保存岗位、状态看板、备注、联系人、提醒和导出。
- 简历匹配型：以 Jobscan、SkillSyncer、Resume Worded 为代表，强调简历与 JD 的关键词差距、匹配分和优化建议。
- 垂直自动化型：面向特定 ATS 或招聘站点做更深的自动化，但通用性较弱。

参考链接：

- Simplify Copilot: https://simplify.jobs/copilot
- Teal Chrome Extension: https://www.tealhq.com/tool/job-search-chrome-extension
- Huntr Job Tracker: https://huntr.co/product/job-tracker
- Jobscan: https://www.jobscan.co/

AI Job Judge 的差异化方向：

- 不绑定 Boss、LinkedIn、某个 ATS，而是面向任意招聘官网。
- 先解决“岗位发现和匹配筛选”，而不是自动投递。
- 用本地规则粗筛 + Claude 精排控制成本。
- 以浏览器插件作为入口，适配登录态、SPA、同页详情和分页。

## 已落地功能

- 简历上传、文本提取、规则生成。
- 当前页面岗位抽取、分页扫描、详情补抓。
- Claude / LLM / heuristic 排序兜底。
- 推荐结果筛选：全部、推荐、可考虑、不建议。
- 扫描模式：快速、均衡、深度。
- 候选上限：控制进入 Claude 精排的候选数量。
- 诊断摘要：列表抽取、详情补抓、分页/滚动、排序诊断。
- 岗位库：保存岗位、状态跟踪、搜索、状态筛选、排序、优先级、备注、标签、截止时间、下一步动作日期、近期/逾期提醒、打开原链接、移除、CSV 导出。
- 投递材料包：从推荐结果或岗位库调用 Claude/API，生成匹配判断、简历突出点、投递备注、面试准备、关键词和风险补强。
- 104 个招聘入口顺序验证样本池。

## 下一阶段优先级

### P0：提升通用抓取可靠性

- 对 `browser_required` 的 Moka、DingTalk、DJI 等 SPA 链接做浏览器真实扫描回归。
- 给 Moka、飞书、北森、Hotjob、自研 ATS 分别沉淀 DOM 家族策略。
- 增加详情链接质量评分：真实详情 URL、同页详情、弹窗详情、列表页回退。

### P1：完善岗位库

- 已完成：备注、标签、截止时间、下一步动作日期。
- 已完成：状态流转，覆盖收藏、准备投递、已投递、面试、放弃。
- 已完成：搜索、状态筛选、优先级排序、近期/逾期提醒、CSV 导出。
- 待完成：投递时间、面试时间。
- 待完成：看板视图。
- 已完成：从岗位库复制定制投递 Prompt。
- 已完成：从推荐结果和岗位库生成投递材料包。
- 待完成：从岗位库重新触发 Claude 复评。

### P2：简历优化闭环

- 针对单个岗位输出缺失关键词和简历改写建议。
- 已完成：支持“复制投递摘要”和“生成投递材料包”。
- 支持导出岗位 + 匹配理由 + 缺口为 Markdown。

### P3：自动填表和投递辅助

- 识别常见申请表字段。
- 用用户确认后的简历结构填充字段。
- 保持不自动提交，只做用户确认前的填充辅助。

## 产品原则

- 不自动投递，避免误投。
- 登录态由用户自己完成，插件只在登录后继续扫描。
- 模型调用只做高价值步骤，不把所有岗位无脑交给模型。
- 所有不确定的详情链接都要显示为“需定位详情”，不能伪装成已捕获。
